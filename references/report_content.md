# Как писать содержание отчёта

Структура зашита в нормах (Cuprins → Introducere → Capitole → Concluzii → Bibliografia). Ниже — что
класть в каждую часть, чтобы отчёт читался как работа, а не как пересказ задания. Объём — по весу
работы: типовая лабораторная по программированию укладывается в 10–15 страниц вместе с приложением.

## Введение (без номера, ~½–1 страница)
1. Одним-двумя предложениями — тема и почему она важна на практике (без воды).
2. **Цель работы** — одно предложение: освоить/реализовать/исследовать X.
3. **Задачи** — 3–5 пунктов (`bullets`), каждый соответствует части отчёта: изучить…, реализовать…, проверить…
4. Если в задании несколько заданий/вариантов — укажи вариант студента.

## Глава 1. Теория / анализ задания
- Минимум теории, нужной, чтобы понять решение: определения, формулы (`equation`), сравнение подходов.
- Условие задания своими словами (безлично) + входные и выходные данные + ограничения.
- Для каждого задания — подраздел 1.1, 1.2: **что нужно получить → какой структурой/алгоритмом решается → почему так**.
- Источники из этой части цитируй `{src:…}`.

## Глава 2. Реализация (ход работы)
Для программирования — по каждому заданию подраздел с повторяющейся схемой:
1. Идея алгоритма и структуры данных (2–5 предложений).
2. Ключевой фрагмент кода (`code` с подписью «Листинг»), 5–25 строк — не весь файл.
3. Разбор: что делает каждая значимая строка/блок, зачем (этот абзац — главное, за что ставят оценку).
4. Особые случаи: ввод, ошибки, граничные значения, как они обрабатываются.
Для не-программных дисциплин (схемотехника, сети, ОС, БД): последовательность шагов эксперимента,
параметры, схемы (`figure`), расчёты (`equation` + пример расчёта с числами из задания).

## Глава 3 (или 2.x). Результаты
- Реальный вывод программы/измерения: `console` или скриншот `figure`; таблица (`table`) с входными и выходными данными.
- Для каждого результата: что подаём на вход → что получили → совпадает ли с ожидаемым (проверка вручную).
- Если есть сравнение (время работы, точность) — таблица или график и **вывод из сравнения**.

## Заключение (без номера, ~½ страницы)
- Что сделано (по задачам из введения, в том же порядке) и какие результаты получены — конкретно, с числами.
- Что показала проверка, какие ограничения решения есть.
- Чему научились / какие навыки закреплены — одним предложением, без пафоса.

## Библиография
Только реальные источники: методичка лабораторной, документация (например, docs.python.org), учебники.
2–6 пунктов хватает. Формат: `Автор. Название. Издатель/сайт, год. URL (дата обращения: ДД.ММ.ГГГГ).`
Не придумывай ISBN, страницы и авторов. Нет уверенных источников — используй методичку и официальную документацию.

## Приложения
- Приложение А — полный код программы (`code`, можно без подписи или с подписями по файлам).
- Приложение Б — дополнительные скриншоты, длинные таблицы данных, контрольный запуск.

## Язык и стиль
- Безлично, прошедшее/настоящее время, термины единообразно (не «словарь» → «dict» → «хеш-таблица» вперемешку).
- Идентификаторы, имена файлов, ключевые слова — в `` `обратных кавычках` ``, чтобы набирались моноширинным.
- Не повторяй текст задания дословно; не используй «как известно», «очевидно», «в наше время».
- Отчёт на румынском — полноценный румынский с диакритикой (ă â î ș ț); на русском — ё где нужна (Артём, Кишинёв).
