# Формат spec.json

Файл — UTF-8 JSON из двух частей: `meta` (титул) и `blocks` (содержимое по порядку). Пример целиком —
`templates/example_spec.json`. Пути к изображениям — относительно папки со spec.

## meta
```json
{
  "lang": "ru",                         // ru | ro | en — язык подписей и титула (по умолчанию ru)
  "lab_number": 3,
  "discipline": "Tehnici de Programare Aplicată",
  "discipline_translation": "Прикладные методы программирования",   // можно опустить
  "topic": "Коллекции данных",
  "teacher": "асист. унив. Н.Ворническу",
  "department": "Departamentul Informatică şi Ingineria Sistemelor", // можно опустить
  "report_title": "RAPORT",             // по умолчанию RAPORT
  "year": 2026,                         // по умолчанию текущий год
  "student": "…", "group": "…",         // только если пользователь явно просит поменять
  "table_caption_align": "right"        // right (норма) | left (как в эталоне) | center
}
```
Постоянные поля (студент, группа, факультет, министерство, университет, город) берутся из `assets/profile.json`.

## Блоки (`blocks`)
Все блоки — объекты с полем `type`.

| type | поля | замечания |
|---|---|---|
| `heading` | `level` (1–3), `text`, `numbered` (по умолчанию true; `false` для Введения/Заключения) | номер `1`, `1.1`, `1.1.1` ставится сам, «Глава» не пиши |
| `p` | `text`, `indent` (см, по умолчанию 1,5) | абзац; поддерживает разметку ниже |
| `bullets` / `numbered` | `items` (список строк) | маркер «–» / «1)», висячий отступ |
| `figure` | `image`, `caption`, `id`, `width_cm` (по умолчанию 14), `max_height_cm` (20) | подпись под рисунком |
| `table` | `header`, `rows`, `caption`, `id`, `col_widths_cm`, `align` (`"l"/"c"/"r"` на колонку) | подпись над таблицей; ячейки поддерживают разметку |
| `code` | `text`, `caption` (необязательно), `id`, `size` (9,5) | моноширинный блок; с `caption` получает «Листинг N» |
| `console` | `text` | вывод программы, без подписи (подписывай через `figure`, если это скриншот) |
| `equation` | `text`, `id` | формула по центру, номер справа |
| `appendix` | `title` | заголовок «Приложение А. Название»; буква ставится сама, дальше идут блоки приложения |
| `sources` | `title` ("Библиография"), `items`: строки или `{"id": "...", "text": "..."}` | нумерованный список; id нужен для `{src:id}` |
| `pagebreak` | — | жёсткий разрыв страницы (почти не нужен: главы начинаются с новой страницы сами) |

Порядок в отчёте: Введение → главы → Заключение → Библиография → Приложения.

## Разметка внутри текста (`p`, `bullets`, ячейки таблиц, подписи)
- `**жирный**`, `*курсив*`, `` `код` `` (Consolas), `^{верхний}`, `_{нижний}` индекс.
- Перекрёстные ссылки подставляют **номер**: `{fig:id}` → `2.1.1`, `{tab:id}`, `{lst:id}`, `{eq:id}`;
  пиши «на рисунке {fig:shot}», «в таблице {tab:data}». Номера расставляются сами, не вписывай их руками.
- `{src:id}` → `[1]`, несколько: `{src:id1,id2}` → `[1, 2]`.
- Ссылаться можно вперёд и назад — номера считаются заранее.

## Частые ошибки
- Вписывание номеров рисунков руками («Рисунок 3») — потеряется синхронизация. Используй `{fig:id}`.
- Два `figure` или два `table` подряд → сборщик остановится; вставь между ними `p`.
- `heading` уровня 1 для «Введения» без `"numbered": false` получит номер 1.
- Длинный код лучше разбить на несколько `code`-блоков с подписями по смыслу, а не одним на 5 страниц.
- Скриншоты: PNG ≥ 1000 px по ширине; код лучше вставлять текстом (`code`), скриншот — для интерфейса/консоли.
